## 모범 답안

### 1단계: 문제의 근본 원인 파악
현재 상황은 **"기능의 중복"** 문제입니다. 100개의 캐릭터가 동일한 `takeDamage()` 로직을 반복 구현하면서:
- 변경 시 모든 클래스를 수정해야 함 (유지보수 악화)
- 버그 발생 시 100곳에서 동시 발생 (버그 전파)
- 새로운 캐릭터 추가 시 코드 중복 (개발 속도 저하)

### 2단계: 상속으로 해결하기

```java
// 📌 기본이 되는 상위 클래스: Character
public abstract class Character {
    protected int health;
    protected int maxHealth;
    protected String name;
    
    // 🎯 모든 캐릭터가 공통으로 사용할 메서드
    public void takeDamage(int damage) {
        int actualDamage = calculateDamageReduction(damage);
        this.health -= actualDamage;
        
        System.out.println(name + "이(가) " + actualDamage + " 피해를 입었습니다!");
        
        if (health <= 0) {
            onDeath();
        }
    }
    
    // 각 캐릭터별로 다르게 동작해야 하는 부분은 추상 메서드로
    protected abstract int calculateDamageReduction(int damage);
    protected abstract void onDeath();
}

// 📌 플레이어: 갑옷으로 데미지 감소
public class Player extends Character {
    private int armor;
    
    @Override
    protected int calculateDamageReduction(int damage) {
        // 플레이어만의 로직: 갑옷으로 감소
        return Math.max(1, damage - armor / 2);
    }
    
    @Override
    protected void onDeath() {
        System.out.println(name + "이(가) 사망하였습니다. 게임 오버!");
    }
}

// 📌 좀비: 재생 능력으로 데미지 증가 저항
public class Zombie extends Character {
    private int regenerationRate;
    
    @Override
    protected int calculateDamageReduction(int damage) {
        // 좀비만의 로직: 재생으로 저항
        return damage - regenerationRate;
    }
    
    @Override
    protected void onDeath() {
        System.out.println(name + "이(가) 완전히 소멸했습니다!");
    }
}

// 📌 보스: 특수 방어 메커니즘
public class Boss extends Character {
    private int shield;
    
    @Override
    protected int calculateDamageReduction(int damage) {
        // 보스만의 로직: 실드 먼저 깎임
        if (shield > 0) {
            shield -= damage;
            return 0;
        }
        return damage;
    }
    
    @Override
    protected void onDeath() {
        System.out.println(name + "을(를) 격파했습니다! 보상 획득!");
    }
}
```

### 3단계: 다형성으로 통합 관리하기

```java
// 📌 핵심: 부모 타입으로 모든 캐릭터를 관리
public class GameManager {
    private List<Character> characters = new ArrayList<>();
    
    // 🎯 캐릭터 타입 상관없이 동일한 코드로 처리
    public void applyDamageToAll(int damage) {
        for (Character character : characters) {
            character.takeDamage(damage);  // ← 다형성!
        }
    }
    
    // 새로운 캐릭터 추가도 간단
    public void addCharacter(Character character) {
        characters.add(character);
    }
}

// 사용 예시
GameManager game = new GameManager();
game.addCharacter(new Player("플레이어"));
game.addCharacter(new Zombie("좀비"));
game.addCharacter(new Boss("최종보스"));

game.applyDamageToAll(20);  // 모든 캐릭터에 20 데미지 적용
// 각 캐릭터가 자신의 방식대로 처리!
```

**결과:**
- ✅ `takeDamage()` 수정 → Character 클래스 1곳만 변경
- ✅ 100개의 캐릭터 자동으로 업데이트
- ✅ 새로운 캐릭터 추가 → Character 상속만 하면 끝

## 핵심 개념 정리

### 🔑 상속 (Inheritance)
- **목적**: 공통 기능을 부모 클래스에 정의하고 자식이 재사용
- **장점**: 코드 중복 제거, 유지보수 용이
- **작성 규칙**: `class Child extends Parent`

```java
// ❌ 나쁜 예: 중복된 코드 100개
public class Player { void takeDamage(int dmg) { health -= dmg; } }
public class Zombie { void takeDamage(int dmg) { health -= dmg; } }
public class Boss { void takeDamage(int dmg) { health -= dmg; } }
// ... 97개 더

// ✅ 좋은 예: 상속으로 통합
public abstract class Character { void takeDamage(int dmg) { } }
```

### 🔑 다형성 (Polymorphism)
- **목적**: 같은 메서드 호출이 객체마다 다르게 동작
- **핵심**: 부모 타입으로 참조하지만 자식의 메서드 실행
- **효과**: "캐릭터 타입을 신경 쓰지 않고" 통일된 방식으로 처리

```java
Character character;
character = new Player();
character.takeDamage(10);   // Player의 takeDamage 실행

character = new Zombie();
character.takeDamage(10);   // Zombie의 takeDamage 실행
// 호출 코드는 동일하지만 실행되는 메서드가 다름!
```

### 🔑 메서드 오버라이딩 (Method Overriding)
- **정의**: 부모 메서드를 자식에서 다시 구현
- **조건**: 메서드명, 파라미터, 반환타입 모두 동일해야 함
- **목적**: 각 객체의 특성에 맞게 동작을 변경

```java
// 부모의 메서드
public class Character {
    public void takeDamage(int damage) { }
}

// 자식의 오버라이딩
public class Player extends Character {
    @Override  // ← 명시적으로 오버라이딩임을 표시
    public void takeDamage(int damage) {
        // Player만의 구현
    }
}
```

### 🔑 추상 클래스 vs 인터페이스

| 구분 | 추상 클래스 | 인터페이스 |
|------|-----------|---------|
| 용도 | "~는" (IS-A) 관계 | "~할 수 있다" (기능 정의) |
| 이 경우 | ✅ Character는 "플레이어다" | Damageable, Healable |
| 구현 | 부분 구현 가능 | 메서드 정의만 (Java 8+) |
| 다중 | 단일 상속만 | 다중 구현 가능 |

## 실무 포인트

### 1️⃣ 설계 원칙: DRY (Don't Repeat Yourself)

```java
// ❌ 변경 지옥: 버그 수정 시 100곳 수정
class Player {
    public void takeDamage(int dmg) {
        health = Math.max(0, health - dmg);  // 버그: maxHealth 초과 가능?
    }
}
// × 99개 클래스에서 동일한 코드 반복...

// ✅ 한 곳만 수정: 모든 캐릭터에 자동 적용
abstract class Character {
    public void takeDamage(int dmg) {
        health = Math.max(0, Math.min(maxHealth, health - dmg));  // 수정 1회
    }
}
```
