### 해결 방식

**1단계: 기본 추상화 (상속 구조 설계)**
```java
// 모든 배송의 공통 인터페이스/추상 클래스
public abstract class Delivery {
    protected String orderId;
    protected String destination;
    
    // 모든 배송이 공통으로 가져야 할 메서드
    public final void startDelivery() {
        validate();
        prepare();  // 배송종류별로 다르게 처리
        send();     // 배송종류별로 다르게 처리
        notifyStart();
    }
    
    public final void completeDelivery() {
        receive();  // 배송종류별로 다르게 처리
        finalize(); // 배송종류별로 다르게 처리
        notifyCompletion();
    }
    
    public final void cancelDelivery() {
        beforeCancel();
        cancel();
        notifyCancel();
    }
    
    // 각 배송 종류에서 구현해야 할 메서드
    protected abstract void prepare();
    protected abstract void send();
    protected abstract void receive();
    protected abstract void finalize();
}
```

**3단계: 배송 관리자 (다형성 활용)**
```java
public class DeliveryManager {
    private List<Delivery> deliveries = new ArrayList<>();
    
    // 배송 종류와 무관하게 동일하게 처리
    public void processDeliveries() {
        for (Delivery delivery : deliveries) {
            delivery.startDelivery();    // 다형성 호출
        }
    }
    
    public void completeDeliveries() {
        for (Delivery delivery : deliveries) {
            delivery.completeDelivery(); // 다형성 호출
        }
    }
    
    public void addDelivery(Delivery delivery) {
        deliveries.add(delivery);  // 어떤 배송이든 추가 가능
    }
}
```

## 핵심 개념 정리

### **상속(Inheritance)**
- **정의**: 공통 특성을 부모 클래스로 추상화하고, 자식 클래스가 이를 물려받음
- **이점**:
  - 코드 중복 제거 (DRY 원칙)
  - 공통 기능을 한 곳에서 관리
  - 계층적 관계 표현
- **이 사례에서**: `Delivery` 추상 클래스가 모든 배송의 공통 워크플로우 정의

### **다형성(Polymorphism)**
- **정의**: 같은 인터페이스로 다양한 구현을 처리하는 능력
- **종류**:
  - **메서드 오버라이딩** (Runtime Polymorphism): 부모 클래스 메서드를 자식이 재정의
  - **메서드 오버로딩** (Compile-time Polymorphism): 같은 이름, 다른 파라미터
- **이 사례에서**: `Delivery` 참조로 `ParcelDelivery`, `FoodDelivery` 등을 처리

### **Template Method Pattern**
```java
// 변하지 않는 알고리즘 구조는 유지
public final void startDelivery() {
    validate();
    prepare();    // 자식이 구현
    send();       // 자식이 구현
    notifyStart();
}
```
- 알고리즘의 골격을 정의하고, 세부사항은 자식에게 위임
- 이 사례의 핵심 패턴

### **개방-폐쇄 원칙 (OCP)**
- **개방**: 새로운 배송 종류 추가에 열려있음 (새 클래스 생성)
- **폐쇄**: 기존 코드 수정에 닫혀있음 (DeliveryManager 수정 불필요)

### **Interface vs Abstract Class**
```java
// 이 경우 abstract class 선택 이유:
// 1. 공통 필드 (orderId, destination) 필요
// 2. 공통 로직 (notifyStart, validate 등) 필요
// 3. 접근 제어자 다양성 (protected) 필요

public abstract class Delivery {  // ✅ 이 사례에 적합
    protected String orderId;
    protected void notifyStart() { }
}
```

## 실무 포인트

### **1. 확장성의 경제성**
```
이전 (다형성 없음):
새 배송 종류 추가 → DeliveryManager 수정 
                   → 기존 if-else 분기 추가
                   → 회귀테스트 필요
                   → 배포 위험도 ↑

이후 (다형성 사용):
새 배송 종류 추가 → 새 클래스만 생성
                   → DeliveryManager 수정 없음
                   → 기존 코드 영향 없음
                   → 배포 위험도 ↓
```
