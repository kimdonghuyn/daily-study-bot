## 모범 답안

현재의 문제점을 먼저 파악하겠습니다.

### ❌ 문제 있는 코드 (Type Checking)
```python
def attack(character):
    if character.type == "warrior":
        print(f"{character.name}이 검으로 베었다!")
    elif character.type == "mage":
        print(f"{character.name}이 마법을 시전했다!")
    elif character.type == "archer":
        print(f"{character.name}이 화살을 쐈다!")
    # 새로운 캐릭터 추가 시마다 elif 추가 필요 😱
```

**문제점:**
- **Open/Closed Principle 위반**: 새로운 캐릭터 추가 시 기존 코드 수정 필요
- **낮은 확장성**: 캐릭터가 100개면 100개의 조건문
- **유지보수 어려움**: 변경점이 분산됨
- **테스트 복잡도 증가**: 모든 케이스를 다시 테스트해야 함

### ✅ 해결책: 상속과 다형성

```python
# 1단계: 추상 기본 클래스 정의 (계약/인터페이스 역할)
from abc import ABC, abstractmethod

class Character(ABC):
    def __init__(self, name):
        self.name = name
    
    @abstractmethod
    def attack(self):
        """각 캐릭터가 자신의 방식으로 공격"""
        pass

# 2단계: 각 캐릭터별 구체적 구현 (다형성)
class Warrior(Character):
    def attack(self):
        return f"{self.name}이 검으로 베었다! 💥"

class Mage(Character):
    def attack(self):
        return f"{self.name}이 파이어볼을 시전했다! 🔥"

class Archer(Character):
    def attack(self):
        return f"{self.name}이 화살을 쐈다! 🏹"

# 3단계: 다형성을 활용한 통일된 사용
def execute_attack(character: Character):
    """Character 타입이면 모두 처리 가능"""
    print(character.attack())

# 실행
characters = [
    Warrior("아서"),
    Mage("머린"),
    Archer("로빈")
]

for char in characters:
    execute_attack(char)  # 각 객체의 실제 타입에 맞는 attack() 호출
```

**출력:**
```
아서이 검으로 베었다! 💥
머린이 파이어볼을 시전했다! 🔥
로빈이 화살을 쐈다! 🏹
```

### 📈 확장성 비교

**새로운 캐릭터 추가 시:**

```python
# 기존 코드는 수정하지 않음! (Open/Closed Principle ✅)
class Paladin(Character):
    def attack(self):
        return f"{self.name}이 신성한 일격을 날렸다! ⚡"

# 기존 코드는 그대로 작동
characters.append(Paladin("우서"))
for char in characters:
    execute_attack(char)  # Paladin도 자동으로 처리됨
```

## 핵심 개념 정리

### 📚 상속 (Inheritance)
- **정의**: 부모 클래스의 속성과 메서드를 자식 클래스가 물려받음
- **목적**: 공통된 특성을 추상화하여 코드 중복 제거
- **예시**: `Warrior`, `Mage`, `Archer` 모두 `Character` 상속

```python
class Warrior(Character):  # Character를 상속
    def attack(self):
        pass
```

### 🎭 다형성 (Polymorphism)
- **정의**: 같은 인터페이스로 다양한 객체를 다룰 수 있는 능력
- **종류**:
  - **컴파일 타임 다형성** (Overloading): Python에서는 제한적
  - **런타임 다형성** (Overriding): 메서드 오버라이딩 ⭐
  
```python
# 런타임에 실제 객체 타입에 따라 다른 attack() 호출
characters = [Warrior(...), Mage(...)]
for char in characters:
    char.attack()  # Warrior면 Warrior의 attack(), Mage면 Mage의 attack()
```

### 🔑 주요 원칙

| 원칙 | 설명 |
|------|------|
| **LSP** (Liskov Substitution) | 자식 클래스는 부모 클래스 자리에 대체 가능 |
| **OCP** (Open/Closed) | 확장에는 열려있고 수정에는 닫혀있어야 함 |
| **DIP** (Dependency Inversion) | 구체적 구현이 아닌 추상화에 의존 |

### 🏢 실제 프로젝트 적용 예

```python
# E-커머스 결제 시스템 예시
from abc import ABC, abstractmethod
from enum import Enum

class PaymentMethod(ABC):
    @abstractmethod
    def validate(self) -> bool:
        pass
    
    @abstractmethod
    def process_payment(self, amount: float) -> dict:
        pass

class CreditCard(PaymentMethod):
    def validate(self) -> bool:
        # 카드 유효성 검사
        return True
    
    def process_payment(self, amount: float) -> dict:
        return {"status": "success", "method": "credit_card"}

class PayPal(PaymentMethod):
    def validate(self) -> bool:
        # PayPal 유효성 검사
        return True
    
    def process_payment(self, amount: float) -> dict:
        return {"status": "success", "method": "paypal"}

# 결제 처리 (새로운 결제 수단 추가해도 코드 불변)
def checkout(payment: PaymentMethod, amount: float):
    if payment.validate():
        return payment.process_payment(amount)
```
