### 1. 🔧 문제 상황

# 상속과 다형성을 통한 게임 몬스터 시스템 설계

## 모범 답안

이 문제는 **상속**으로 코드 중복을 제거하고, **다형성**으로 각 몬스터의 고유한 행동을 유연하게 처리하는 전형적인 사례입니다.

### 문제 상황 분석
- ❌ **현재**: 몬스터마다 중복된 코드 (생명력, 이동, 공격 등)
- ❌ **현재**: 새 몬스터 추가 시 기존 코드 수정 필요
- ❌ **현재**: 모든 몬스터 제어 로직이 분산됨

### 해결 방안: 상속과 다형성의 조합

```java
// 1단계: 기본 틀 정의 (상속)
abstract class Monster {
    protected String name;
    protected int hp;
    protected int x, y;
    
    public Monster(String name, int hp) {
        this.name = name;
        this.hp = hp;
    }
    
    // 공통 동작
    public void takeDamage(int damage) {
        this.hp -= damage;
        System.out.println(name + "이(가) " + damage + "의 피해를 입었습니다!");
    }
    
    // 다형성: 각 몬스터가 구현해야 할 메서드
    abstract void makeSound();
    abstract void move();
    abstract void attack();
}

// 2단계: 구체적 몬스터들 (다형성)
class Dragon extends Monster {
    public Dragon() {
        super("드래곤", 100);
    }
    
    @Override
    void makeSound() {
        System.out.println("🐉 ROAAAARRR! (웅장한 울음)");
    }
    
    @Override
    void move() {
        System.out.println("드래곤이 하늘을 날며 이동합니다.");
        x += 20; y += 20;
    }
    
    @Override
    void attack() {
        System.out.println("드래곤이 불을 뿜습니다! 💥");
    }
}

class Zombie extends Monster {
    public Zombie() {
        super("좀비", 30);
    }
    
    @Override
    void makeSound() {
        System.out.println("🧟 Uuuuugh... (신음)");
    }
    
    @Override
    void move() {
        System.out.println("좀비가 느리게 걸어옵니다.");
        x += 2;
    }
    
    @Override
    void attack() {
        System.out.println("좀비가 손톱으로 할퀴려고 합니다! 🤲");
    }
}

class Slime extends Monster {
    public Slime() {
        super("슬라임", 15);
    }
    
    @Override
    void makeSound() {
        System.out.println("🟢 Pquelp... (부글거리는 소리)");
    }
    
    @Override
    void move() {
        System.out.println("슬라임이 튀어다닙니다.");
        x += 5;
    }
    
    @Override
    void attack() {
        System.out.println("슬라임이 산을 분사합니다! 💧");
    }
}

// 3단계: 다형성의 진가 - 모든 몬스터를 동일하게 처리!
class GameManager {
    private List<Monster> monsters = new ArrayList<>();
    
    public void addMonster(Monster monster) {
        monsters.add(monster);
    }
    
    // 핵심: 실제 타입을 신경쓰지 않고 공통 인터페이스로 처리
    public void attackAllMonsters() {
        for (Monster monster : monsters) {
            monster.makeSound();  // 각 몬스터마다 다른 소리!
            monster.move();       // 각 몬스터마다 다른 이동!
            monster.attack();     // 각 몬스터마다 다른 공격!
            monster.takeDamage(10); // 공통 동작
        }
    }
}

// 실행 예제
public class Main {
    public static void main(String[] args) {
        GameManager game = new GameManager();
        game.addMonster(new Dragon());
        game.addMonster(new Zombie());
        game.addMonster(new Slime());
        
        game.attackAllMonsters();
        /* 출력:
        🐉 ROAAAARRR! (웅장한 울음)
        드래곤이 하늘을 날며 이동합니다.
        드래곤이 불을 뿜습니다! 💥
        드래곤이(가) 10의 피해를 입었습니다!
        
        🧟 Uuuuugh... (신음)
        좀비가 느리게 걸어옵니다.
        좀비가 손톱으로 할퀴려고 합니다! 🤲
        좀비이(가) 10의 피해를 입었습니다!
        
        🟢 Pquelp... (부글거리는 소리)
        슬라임이 튀어다닙니다.
        슬라임이 산을 분사합니다! 💧
        슬라임이(가) 10의 피해를 입었습니다!
        */
    }
}
```

## 핵심 개념 정리

### 📌 상속 (Inheritance)
- **목적**: 코드 중복 제거, 공통 기능 통합
- **개념**: 부모 클래스(Monster)의 속성과 메서드를 자식 클래스가 물려받음
- **이점**:
  - `takeDamage()` 같은 공통 로직을 한 번만 작성
  - 새로운 몬스터 추가 시 기본 기능은 자동으로 가짐
  - 유지보수 시 공통 부분만 수정하면 모든 몬스터에 반영

### 📌 다형성 (Polymorphism)
- **목적**: 같은 이름의 메서드가 다르게 동작
- **개념**: `Monster` 타입으로 참조하지만, 실제 객체의 메서드가 실행됨
- **원리 (동적 바인딩)**:
  ```java
  Monster monster = new Dragon();  // 부모 타입, 자식 객체
  monster.makeSound();              // Dragon의 makeSound() 실행!
  ```
- **이점**:
  - 새 몬스터가 추가되어도 `GameManager` 코드 변경 없음
  - `List<Monster>`에 모든 몬스터를 통합 관리
  - 루프 한 번으로 모든 몬스터 처리 가능

### 📌 추상 클래스 (Abstract Class)
- **역할**: 부분적 구현 + 강제 규약
- **특징**:
  - 인스턴스 생성 불가 (프레임워크 역할)
  - `abstract` 메서드는 반드시 오버라이드 필요
  - 공통 구현(`takeDamage`)과 규약(`makeSound`)을 함께 제공

### 📌 메서드 오버라이딩 (Method Overriding)
- **정의**: 부모의 메서드를 자식이 다시 구현
- **조건**: 메서드 시그니처는 동일, 구현(body)만 변경

## 실무 포인트

### 🎯 확장성 (Open-Closed Principle)
```java
// 새로운 몬스터 추가 시
class Phoenix extends Monster {
    @Override
    void makeSound() { System.out.println("🔥 Screeeee!"); }
    @Override
    void move() { System.out.println("불꽃을 흩으며 날아다닙니다."); }
    @Override
    void attack() { System.out.println("불의 폭풍을 일으킵니다!"); }
}

// GameManager는 수정 필요 없음!
game.addMonster(new Phoenix());
game.attackAllMonsters(); // 자동으로 Phoenix도 포함
```
