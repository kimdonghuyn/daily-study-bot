# 상속과 다형성: 게임 캐릭터 시스템 설계

## 모범 답안

이 문제는 **상속과 다형성의 가장 전형적인 사용 사례**입니다.

### 문제 분석
당신의 코드가 겪고 있는 문제:
1. **코드 중복**: 모든 캐릭터가 이름, HP, 경험치 등 공통 속성을 반복 정의
2. **Open/Closed 원칙 위반**: 새 캐릭터 추가 시 메인 로직 수정 필요
3. **유지보수 어려움**: 공통 로직 변경 시 모든 클래스를 수정해야 함

### 해결 방법: 상속과 다형성

```python
# ✅ 올바른 설계
from abc import ABC, abstractmethod

# 1단계: 공통 기능을 담은 부모 클래스 (상속의 핵심)
class Character(ABC):
    def __init__(self, name: str, hp: int):
        self.name = name
        self.hp = hp
        self.exp = 0
    
    # 다형성: 자식이 구현할 메서드 정의
    @abstractmethod
    def attack(self) -> str:
        pass
    
    def take_damage(self, damage: int):
        self.hp -= damage
        print(f"{self.name}이(가) {damage} 데미지를 입었습니다!")
    
    def gain_exp(self, amount: int):
        self.exp += amount

# 2단계: 자식 클래스들 (다형성 구현)
class Warrior(Character):
    def attack(self) -> str:
        return f"{self.name}이(가) 칼로 베기를 사용합니다! (100 데미지)"

class Mage(Character):
    def attack(self) -> str:
        return f"{self.name}이(가) 파이어볼을 발동합니다! (150 데미지)"

class Archer(Character):
    def attack(self) -> str:
        return f"{self.name}이(가) 화살을 쏩니다! (80 데미지)"

# 3단계: 메인 게임 로직 (다형성의 강력함!)
class GameEngine:
    def __init__(self):
        self.characters: list[Character] = []
    
    def add_character(self, character: Character):
        self.characters.append(character)
    
    # 모든 캐릭터를 동일하게 처리! (다형성)
    def start_battle(self):
        for character in self.characters:
            print(character.attack())  # 실제 타입에 맞는 attack() 실행
            character.gain_exp(100)

# 사용 예시
game = GameEngine()
game.add_character(Warrior("아서", hp=100))
game.add_character(Mage("메를린", hp=60))
game.add_character(Archer("로빈", hp=80))

game.start_battle()

# 출력:
# 아서이(가) 칼로 베기를 사용합니다! (100 데미지)
# 메를린이(가) 파이어볼을 발동합니다! (150 데미지)
# 로빈이(가) 화살을 쏩니다! (80 데미지)
```

## 핵심 개념 정리

### 📌 상속 (Inheritance)
- **정의**: 부모 클래스의 속성과 메서드를 자식 클래스가 물려받음
- **장점**:
  - 공통 코드를 한 곳에서 관리
  - 공통 기능 변경 시 한 번만 수정
  - 계층적 구조로 관계 명확화
- **우리 예시**: `Character` → `Warrior`, `Mage`, `Archer`

### 📌 다형성 (Polymorphism)
- **정의**: 같은 메서드명이지만 객체의 실제 타입에 따라 다르게 동작
- **구현 방식**:
  - **메서드 오버라이딩**: 부모의 메서드를 자식이 다시 구현
  - **추상 메서드**: 부모에서 구조만 정의, 자식이 구현 강제
- **우리 예시**: 모든 캐릭터의 `attack()`이 다르게 동작

### 📌 추상 클래스 (Abstract Class)
```python
from abc import ABC, abstractmethod

class Character(ABC):  # 직접 인스턴스 생성 불가
    @abstractmethod
    def attack(self):  # 반드시 구현해야 함
        pass
```
- 부모 클래스가 "설계도"의 역할
- 자식은 반드시 추상 메서드를 구현해야 함

### 📌 Liskov Substitution Principle (LSP)
```python
def perform_attack(character: Character):
    print(character.attack())

# 어떤 Character 타입이든 작동!
perform_attack(Warrior("아서", 100))
perform_attack(Mage("메를린", 60))
```
- 부모 타입의 변수에 자식 타입을 대입 가능
- "자식 클래스는 부모 클래스의 역할을 완벽하게 할 수 있어야 함"
