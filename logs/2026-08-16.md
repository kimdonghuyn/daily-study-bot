## 📚 모범 답안 & 개념 정리

### 1. 🔧 문제 상황

# 상속과 다형성을 통한 무기 시스템 개선

## 모범 답안

**현재의 문제점:**
각 무기마다 독립적인 함수를 만들어서 관리하면, 코드가 중복되고 변경에 취약합니다.

**상속과 다형성의 해결책:**

```python
# ❌ 개선 전: 반복되는 코드
def attack_sword():
    damage = 100
    print(f"검 공격: {damage} 데미지")

def attack_bow():
    damage = 50
    print(f"활 공격: {damage} 데미지")

def attack_magic():
    damage = 80
    print(f"마법 공격: {damage} 데미지")

# 새 무기 추가 시마다 함수 추가 필요 😞


# ✅ 개선 후: 상속과 다형성 활용
from abc import ABC, abstractmethod

# 1️⃣ 공통 인터페이스 정의 (상속의 기반)
class Weapon(ABC):
    def __init__(self, name):
        self.name = name
    
    @abstractmethod
    def get_damage(self):
        """각 무기별로 구현"""
        pass
    
    def attack(self):
        """모든 무기에서 동일한 공격 로직"""
        damage = self.get_damage()
        print(f"{self.name} 공격: {damage} 데미지")

# 2️⃣ 구체적인 무기들 (상속으로 재사용)
class Sword(Weapon):
    def get_damage(self):
        return 100

class Bow(Weapon):
    def get_damage(self):
        return 50

class Magic(Weapon):
    def get_damage(self):
        return 80

# 3️⃣ 다형성: 같은 인터페이스로 다르게 동작
weapons = [Sword("롱소드"), Bow("엘프 활"), Magic("파이어볼")]

for weapon in weapons:
    weapon.attack()  # 각각 다르게 동작! 
    # 롱소드 공격: 100 데미지
    # 엘프 활 공격: 50 데미지
    # 파이어볼 공격: 80 데미지
```

**이제 요구사항이 변경되면?**

```python
# 📌 새로운 요구사항: "모든 무기 데미지 2배"
class Weapon(ABC):
    def __init__(self, name):
        self.name = name
        self.damage_multiplier = 2  # 한 곳만 수정!
    
    @abstractmethod
    def get_damage(self):
        pass
    
    def attack(self):
        damage = self.get_damage() * self.damage_multiplier  # 한 줄만 추가
        print(f"{self.name} 공격: {damage} 데미지")

# 모든 무기가 자동으로 2배 데미지를 가짐 ✨
```

## 핵심 개념 정리

### **1. 상속 (Inheritance)**
- **목적**: 공통의 속성/메서드를 부모 클래스에서 정의하고 자식이 재사용
- **효과**: 중복 코드 제거, 코드 재사용성 증대
- **이 예시에서**: `Weapon` 클래스의 `attack()` 로직을 모든 무기가 상속받음

### **2. 다형성 (Polymorphism)**
- **목적**: 같은 메서드 이름이지만 구체적인 동작은 각 클래스마다 다르게
- **효과**: 새로운 무기 추가 시 기존 코드 수정 없음 (OCP 준수)
- **이 예시에서**: `get_damage()`는 각 무기마다 다른 값을 반환

### **3. 추상 클래스 (Abstract Class)**
```python
@abstractmethod  # 자식이 반드시 구현해야 하는 메서드
def get_damage(self):
    pass
```
- 계약(contract)을 강제함
- 모든 무기는 반드시 `get_damage()` 구현 필요

### **4. OCP (Open/Closed Principle)**
- **Open for extension**: 새 무기 추가는 쉬움 (새 클래스 만들기)
- **Closed for modification**: 기존 코드 수정 불필요

## 실무 포인트

### **1. 확장성 (Scalability)**
```python
# 새로운 무기 추가가 간단함
class Crossbow(Weapon):
    def get_damage(self):
        return 75

# 기존 코드는 수정할 필요 없음!
weapons.append(Crossbow("쇠뇌"))
```

### **2. 유지보수성 (Maintainability)**
```python
# 공통 로직 변경 시 한 곳만 수정
class Weapon(ABC):
    def attack(self):
        damage = self.get_damage()
        crit_chance = 0.15  # 크리티컬 확률 추가
        if random.random() < crit_chance:
            damage *= 2
        print(f"{self.name} 공격: {damage} 데미지")

# 모든 무기에 자동 적용됨
```

### **3. 테스트 용이성**
```python
# Mock 객체 생성이 쉬움
class MockWeapon(Weapon):
    def get_damage(self):
        return 999

# 테스트 코드 작성 간단
def test_attack():
    weapon = MockWeapon("테스트무기")
    weapon.attack()  # 예측 가능한 동작
```

### **4. 실제 프로젝트 예시**

```python
# 게임 엔진, 결제 시스템 등에서 광범위하게 사용됨
class PaymentMethod(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

class CreditCard(PaymentMethod):
    def pay(self, amount):
        # 신용카드 결제 로직
        pass

class MobilePayment(PaymentMethod):
    def pay(self, amount):
        # 모바일 결제 로직
        pass

# 결제 시스템은 PaymentMethod만 신경쓰면 됨
def process_payment(payment_method: PaymentMethod, amount):
    payment_method.pay(amount)
```

## 요약: Before vs After

| 항목 | ❌ Before | ✅ After |
|------|----------|---------|
| 새 무기 추가 | 함수 하나 추가 | 클래스 하나 추가 |
| 공통 로직 수정 | 수십 함수 수정 | 부모 클래스만 수정 |
| 코드 이해 난이도 | 높음 (반복 코드) | 낮음 (구조화됨) |
| 테스트 | 어려움 | 쉬움 |
| 변경에 대한 영향범위 | 크다 | 작다 |
