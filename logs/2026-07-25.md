## 📚 모범 답안 & 개념 정리

### 1. 🔧 문제 상황

# 상속과 다형성을 통한 게임 캐릭터 시스템 설계

## 모범 답안

**문제의 근본 원인은 "타입 기반 분기"입니다.** 새 캐릭터마다 조건문을 추가하는 구조는 **Open-Closed Principle을 위반**하고 있습니다.

### 해결책: 상속과 다형성

```python
# ❌ 현재 코드 (문제점)
def attack(character):
    if character.type == "warrior":
        print(f"{character.name}이(가) 칼로 베기!")
    elif character.type == "wizard":
        print(f"{character.name}이(가) 마법 시전!")
    elif character.type == "archer":
        print(f"{character.name}이(가) 화살 발사!")
    # 50개 추가되면 50개의 elif...

# ✅ 개선된 코드 (상속 + 다형성)
from abc import ABC, abstractmethod

class Character(ABC):
    """모든 캐릭터의 기본 구조를 정의"""
    def __init__(self, name, hp):
        self.name = name
        self.hp = hp
    
    @abstractmethod
    def attack(self):
        """각 캐릭터가 구현해야 할 메서드"""
        pass
    
    def take_damage(self, damage):
        """공통 메서드"""
        self.hp -= damage
        print(f"{self.name}이(가) {damage} 피해를 입었습니다!")

class Warrior(Character):
    def attack(self):
        return f"{self.name}이(가) 칼로 베기! [데미지: 20]"

class Wizard(Character):
    def attack(self):
        return f"{self.name}이(가) 파이어볼 시전! [데미지: 30]"

class Archer(Character):
    def attack(self):
        return f"{self.name}이(가) 화살 발사! [데미지: 15]"

class Paladin(Character):  # 새 캐릭터 추가
    def attack(self):
        return f"{self.name}이(가) 신성한 빛으로 공격! [데미지: 25]"

# 핵심: 클라이언트 코드는 변경되지 않음!
def battle_system(characters: list[Character]):
    """캐릭터 개수와 종류와 관계없이 동일한 코드"""
    for character in characters:
        print(character.attack())  # 다형성: 각 객체의 attack() 호출

# 사용
characters = [
    Warrior("아서", 100),
    Wizard("머린", 80),
    Archer("로빈", 70),
    Paladin("우서", 90)  # 새 캐릭터 추가해도 battle_system 코드 변경 안 함!
]

battle_system(characters)
```

### 출력 결과
```
아서이(가) 칼로 베기! [데미지: 20]
머린이(가) 파이어볼 시전! [데미지: 30]
로빈이(가) 화살 발사! [데미지: 15]
우서이(가) 신성한 빛으로 공격! [데미지: 25]
```

## 핵심 개념 정리

### 1️⃣ **상속 (Inheritance)**
- 공통된 속성/메서드를 부모 클래스에서 정의
- 자식 클래스가 부모의 기능을 물려받음
- "is-a" 관계: "전사는 캐릭터이다"

### 2️⃣ **다형성 (Polymorphism)**
```python
# 같은 메서드명이지만 다르게 동작
warrior.attack()  # 칼로 베기
wizard.attack()   # 마법 시전
archer.attack()   # 화살 발사
```
- **메서드 오버라이딩**: 자식이 부모의 메서드를 재정의
- **동적 바인딩**: 런타임에 실제 객체 타입에 따라 메서드 결정

### 3️⃣ **추상화 (Abstraction)**
```python
class Character(ABC):
    @abstractmethod
    def attack(self):
        pass  # 자식이 반드시 구현해야 함
```
- 인터페이스 계약 정의
- 구현을 강제하여 일관성 보장

### 4️⃣ **SOLID 원칙**
| 원칙 | 설명 | 이 예제에서 |
|------|------|----------|
| **O** | Open-Closed | 새 캐릭터 추가에 열려있고, 기존 코드 수정에 닫혀있음 |
| **L** | Liskov Substitution | 어떤 Character 객체든 대체 가능 |
| **D** | Dependency Inversion | `battle_system`은 구체적 클래스 아닌 Character 인터페이스에 의존 |

## 실무 포인트

### 🎯 **Before vs After 비교**

| 측면 | 조건문 방식 | 상속+다형성 방식 |
|------|----------|----------------|
| **새 캐릭터 추가 시** | 조건문 추가 필요 | 새 클래스만 생성 |
| **버그 위험** | 분기 로직 누락 가능 | 추상 메서드로 강제 |
| **코드 가독성** | 길고 복잡함 | 간결하고 명확함 |
| **테스트** | 각 분기마다 테스트 | 개별 클래스만 테스트 |
| **유지보수** | 어려움 (변경 영향도 큼) | 용이함 (격리됨) |

### 📋 **실제 확장 예제**

```python
# 게임 난이도에 따른 데미지 조정
class Character(ABC):
    def __init__(self, name, hp, difficulty="normal"):
        self.name = name
        self.hp = hp
        self.difficulty = difficulty
    
    @abstractmethod
    def get_damage(self) -> int:
        pass
    
    def attack(self):
        damage = self.get_damage()
        multiplier = {"easy": 0.8, "normal": 1.0, "hard": 1.2}
        final_damage = damage * multiplier[self.difficulty]
        return f"{self.name}: {final_damage} 데미지"

class Warrior(Character):
    def get_damage(self) -> int:
        return 20

class Wizard(Character):
    def get_damage(self) -> int:
        return 30

# 역시 클라이언트 코드 변경 없음!
```

### ⚠️ **주의사항**

```python
# ❌ 하지 말아야 할 것
class Warrior:
    pass
class Wizard:
    pass
# → 공통 인터페이스 없음, 타입 체크 필요

# ✅ 해야 할 것
class Character(ABC):  # 공통 계약 정의
    @abstractmethod
    def attack(self):
        pass
```

### 💡 **실무 팁**

2. **메서드 시그니처 문서화**

   ```python
   def attack(self) -> str:

       """
   ```

3. **팩토리 패턴으로 객체 생성 관리**
   ```python
   class CharacterFactory:
       @staticmethod
       def create(char_type: str, name: str) -> Character:
           types = {
               "warrior": Warrior,
               "wizard": Wizard,
               "archer": Archer,
           }
           return types[char_type](name, hp=100)
   ```

## 결론

✅ **50개 캐릭터 추가 시:**
- 조건문 방식: 50개의 elif 추가
- 상속+다형성: 50개의 새 클래스 생성 (기존 코드 변경 0줄)

**이것이 바로 "확장에는 열려있고, 수정에는 닫혀있다"는 OOP의 진가입니다.**
