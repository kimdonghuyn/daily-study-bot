```java
class Player {
    int hp;
    int x, y;

    void die() { System.out.println("몬스터 죽음"); }
}

class NPC {
    int hp;

    void move(int dx, int dy) { x += dx; y += dy; }  // 중복!
    // ...
}
```

```java
// ✅ 해결: 상속으로 공통 코드 추출
abstract class Character {
    protected int hp;
    protected int x, y;
    
    // 공통 행동
    public void move(int dx, int dy) {
        x += dx;
        y += dy;
    }
    
    public void takeDamage(int damage) {
        hp -= damage;
        if (hp <= 0) {
            die();
        }
    }
    
    // 서브클래스가 구현해야 할 행동
    abstract void die();
}

class Player extends Character {
    @Override
    void die() {
        System.out.println("플레이어 죽음 - 게임 오버");
        // 플레이어만의 로직
    }
}

class Monster extends Character {
    @Override
    void die() {
        System.out.println("몬스터 죽음 - 경험치 획득");
        // 몬스터만의 로직
    }
}

class NPC extends Character {
    @Override
    void die() {
        System.out.println("NPC 죽음 - 퀘스트 실패");
    }
}
```

**상속의 효과:**
- 코드 양 50% 감소
- hp, x, y 같은 속성을 한 곳에서만 관리
- move() 수정 시 모든 캐릭터에 자동 반영

```java
// ❌ 상속만으로는 부족한 상황
List<Player> players = new ArrayList<>();
List<Monster> monsters = new ArrayList<>();
List<NPC> npcs = new ArrayList<>();

// 게임 루프: 모든 캐릭터를 움직여야 함
for (Player p : players) p.move(1, 1);
for (Monster m : monsters) m.move(1, 1);
for (NPC n : npcs) n.move(1, 1);

// 데미지 처리: 반복되는 코드
for (Player p : players) p.takeDamage(10);
for (Monster m : monsters) m.takeDamage(10);
for (NPC n : npcs) n.takeDamage(10);
```


**다형성의 효과:**
- 캐릭터 타입을 신경쓰지 않고 `Character` 인터페이스로 통합 처리
- 새로운 캐릭터 타입 추가 시 게임 루프 수정 불필요
- 유지보수성과 확장성 극대화

## 핵심 개념 정리

### 🔷 상속 (Inheritance)
- **정의**: 부모 클래스의 속성과 메서드를 자식 클래스가 물려받음
- **목적**: **코드 중복 제거** → DRY 원칙
- **문제 해결**:
  ```
  복사-붙여넣기 → 부모 클래스 추출 → 한 곳에서 관리
  ```
- **주의**: "IS-A" 관계 필요 (Player IS-A Character)
  ```
  ❌ class Sword extends Character (말이 안 됨)
  ✅ class Player extends Character (합리적)
  ```

### 🔷 다형성 (Polymorphism)
- **정의**: 같은 메서드 호출이 객체 타입에 따라 다르게 동작
- **메커니즘**: 동적 바인딩(Runtime에 실제 객체의 메서드 호출)
- **효과**: **타입 무관한 통합 관리**
  ```java
  Character c = new Monster();  // 부모 타입으로 참조
  c.die();  // Monster의 die() 실행
  ```
- **3가지 형태**:
  1. **메서드 오버라이딩** (Method Overriding) - 가장 중요
  2. **메서드 오버로딩** (Method Overloading) - 컴파일 타임
  3. **인터페이스 구현** (Interface) - 계약 기반

### 🔷 추상 클래스 vs 인터페이스
| 항목 | 추상 클래스 | 인터페이스 |
|------|----------|---------|
| 상태(필드) | ✅ 보유 가능 | ❌ 상수만 |
| 구현 | ✅ 메서드 구현 | ❌ 구현 불가 (Java 8+ default 제외) |
| 상속 | 단일만 가능 | 다중 구현 가능 |
| 용도 | 관련된 클래스의 공통 구조 | 계약/능력 정의 |
