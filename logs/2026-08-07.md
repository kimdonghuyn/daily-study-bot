### 1. 🔧 문제 상황

# 상속과 다형성: 음식 배달 앱 설계

## 모범 답안

이 상황은 **상속(Inheritance)**과 **다형성(Polymorphism)**으로 해결합니다.

### 문제 분석
- 피자집, 치킨집, 한식당 → 모두 "음식점"이라는 공통점
- 공통 작업(영업시간, 메뉴, 리뷰) + 각자 다른 구현 필요
- 반복되는 코드를 부모 클래스로 통합하고, 차이점을 자식 클래스에서 구현

### 설계 솔루션

```python
# 1️⃣ 부모 클래스: 모든 음식점의 공통 구조 정의
class Restaurant:
    def __init__(self, name, location):
        self.name = name
        self.location = location
        self.rating = 4.5
    
    # 공통 메서드
    def get_operating_hours(self):
        """영업시간 확인 (모든 식당이 구현해야 함)"""
        raise NotImplementedError("서브클래스에서 구현하세요")
    
    def get_menu(self):
        """메뉴 받아오기"""
        raise NotImplementedError("서브클래스에서 구현하세요")
    
    def show_reviews(self):
        """공통 로직: 모든 식당이 동일"""
        return f"{self.name}의 리뷰 (평점: {self.rating}★)"

# 2️⃣ 자식 클래스들: 각 음식점 유형별 구현
class PizzaShop(Restaurant):
    def get_operating_hours(self):
        return "피자집: 11:00 ~ 23:00 (일요일 휴무)"
    
    def get_menu(self):
        return ["마르게리타", "페퍼로니", "베지타리안"]

class ChickenShop(Restaurant):
    def get_operating_hours(self):
        return "치킨집: 16:00 ~ 02:00 (연중무휴)"
    
    def get_menu(self):
        return ["한마리", "반마리", "순살너겟"]

class KoreanRestaurant(Restaurant):
    def get_operating_hours(self):
        return "한식당: 10:30 ~ 22:00"
    
    def get_menu(self):
        return ["김밥", "떡볶이", "순두부찌개"]

# 3️⃣ 다형성 활용: 같은 방식으로 모두 처리
def show_restaurant_info(restaurant):
    """Restaurant 타입이면 뭐든 처리 가능"""
    print(f"\n🏪 {restaurant.name} ({restaurant.location})")
    print(f"⏰ {restaurant.get_operating_hours()}")
    print(f"📋 메뉴: {restaurant.get_menu()}")
    print(f"⭐ {restaurant.show_reviews()}")

# 실행
restaurants = [
    PizzaShop("도미노", "강남"),
    ChickenShop("BBQ", "서초"),
    KoreanRestaurant("고향반찬", "역삼")
]

for restaurant in restaurants:
    show_restaurant_info(restaurant)
```

```
...
```

## 핵심 개념 정리

### 1. **상속 (Inheritance)**
- **정의**: 부모 클래스의 특성을 자식 클래스가 물려받음
- **목적**: 코드 중복 제거, 공통 기능 통합
- **문법**: `class Child(Parent)`
- **여기서**: `Restaurant`가 부모, `PizzaShop`, `ChickenShop` 등이 자식

### 2. **다형성 (Polymorphism)**
- **정의**: 같은 이름의 메서드가 객체마다 다르게 동작
- **핵심**: "같은 인터페이스, 다른 구현"
- **메서드 오버라이딩**: 자식이 부모 메서드를 자신의 방식으로 재정의
- **여기서**: `get_operating_hours()`를 각 식당이 다르게 구현

### 3. **추상 메서드 (Abstract Method)**
```python
# Python에서 강제하는 방법
from abc import ABC, abstractmethod

class Restaurant(ABC):  # 추상 클래스
    @abstractmethod
    def get_menu(self):
        pass  # 반드시 자식이 구현해야 함
```

### 4. **메서드 해결 순서 (MRO)**
```
자식 클래스 → 부모 클래스 → 그 위의 부모 → ...
```

## 실무 포인트

### ✅ 즉시 적용할 수 있는 팁

#### 1. **새로운 음식점 추가가 쉬워짐**
```python
# 중국음식점 추가 - 3줄이면 끝!
class ChineseRestaurant(Restaurant):
    def get_operating_hours(self):
        return "중국음식점: 11:30 ~ 21:30"
    def get_menu(self):
        return ["마라탕", "깐풍기", "짜장면"]
```

#### 2. **공통 기능 변경도 간단**
```python
# 모든 식당의 리뷰 표시 형식을 바꾸려면?
# Restaurant.show_reviews()만 수정하면 모두 적용됨 ✨
class Restaurant:
    def show_reviews(self):
        return f"✨ {self.name} | {self.rating}점 (평점순)"
```

#### 3. **루프로 일괄 처리**
```python
# 모든 음식점 정보를 DB에 저장
for restaurant in restaurants:
    save_to_db(restaurant.get_menu())
    # 타입 상관없이 동일하게 처리 가능!
```

### 🚨 주의사항

| 상황 | ❌ 피해야 할 것 | ✅ 해야 할 것 |
|------|---|---|
| 모든 음식점이 공통으로 가진 속성 | 각각 만들기 | 부모 클래스에서 정의 |
| 메뉴 가져오기 같은 필수 기능 | 일부만 구현 | 추상 메서드로 강제 |
| 조회 로직 변경 | 모든 자식을 수정 | 부모만 수정 |
| 타입 검증 | `if type(x) == PizzaShop` | `isinstance(x, Restaurant)` |

### 📈 성장 시나리오

```
1단계: 3가지 음식점 타입 → 상속으로 해결

3단계: 음식점 등급(프리미엄, 일반) → 다중 상속/믹스인 활용
4단계: 다양한 배송 방식 → 새로운 다형성 구조 추가
```

## 결론

**"상속과 다형성은 변화하는 요구사항에 대응하는 설계 원칙입니다."**

- 음식점이 100개 추가되어도 기존 코드는 건드리지 않음 (Open-Closed Principle)
- 각 식당의 고유 로직은 자신의 클래스에만 존재 (Single Responsibility)
- 새로운 음식점 타입도
