## 📚 모범 답안 & 개념 정리

### 1. 🔧 문제 상황

# 상속과 다형성을 활용한 음식 배달 앱 설계

## 모범 답안

이 문제는 **상속(Inheritance)**과 **다형성(Polymorphism)**을 활용하여 해결할 수 있습니다.

### 1단계: 공통 인터페이스/추상 클래스 정의
```java
// 모든 음식 주문이 따를 기본 구조 정의
abstract class FoodOrder {
    protected String foodName;
    protected String orderId;
    
    // Template Method Pattern: 공통 프로세스 정의
    public final void processOrder() {
        prepare();      // 각 음식마다 다르게 구현
        pack();         // 공통 로직
        deliver();      // 공통 로직
    }
    
    // 서브클래스에서 반드시 구현해야 할 메서드
    abstract void prepare();
    
    // 공통 로직은 여기서 구현
    protected void pack() {
        System.out.println(foodName + "을(를) 박스에 담습니다");
    }
    
    protected void deliver() {
        System.out.println("배달을 시작합니다 - 주문번호: " + orderId);
    }
}
```

### 2단계: 각 음식별 구체적 구현
```java
class PizzaOrder extends FoodOrder {
    public PizzaOrder(String orderId) {
        this.foodName = "피자";
        this.orderId = orderId;
    }
    
    @Override
    void prepare() {
        System.out.println("오븐에서 피자를 굽습니다 (180°C, 15분)");
    }
}

class ChickenOrder extends FoodOrder {
    public ChickenOrder(String orderId) {
        this.foodName = "치킨";
        this.orderId = orderId;
    }
    
    @Override
    void prepare() {
        System.out.println("기름에 치킨을 튀깁니다 (170°C, 20분)");
    }
}

class SushiOrder extends FoodOrder {
    public SushiOrder(String orderId) {
        this.foodName = "초밥";
        this.orderId = orderId;
    }
    
    @Override
    void prepare() {
        System.out.println("신선한 재료로 초밥을 준비합니다");
    }
}
```

### 3단계: 다형성을 이용한 클라이언트 코드
```java
public class OrderProcessor {
    // 다형성: FoodOrder 타입 하나로 모든 음식 처리
    public void executeOrder(FoodOrder order) {
        order.processOrder();  // 실제 객체 타입에 맞게 자동 실행
    }
    
    public static void main(String[] args) {
        OrderProcessor processor = new OrderProcessor();
        
        FoodOrder order1 = new PizzaOrder("ORD001");
        FoodOrder order2 = new ChickenOrder("ORD002");
        FoodOrder order3 = new SushiOrder("ORD003");
        
        // 모두 동일한 인터페이스로 처리
        processor.executeOrder(order1);
        processor.executeOrder(order2);
        processor.executeOrder(order3);
    }
}
```

```

배달을 시작합니다 - 주문번호: ORD003
```

## 핵심 개념 정리

### 📌 상속(Inheritance)
- **정의**: 기존 클래스의 속성과 메서드를 새로운 클래스가 물려받는 것
- **목적**: 코드 재사용성 증대, DRY(Don't Repeat Yourself) 원칙
- **이 예제에서**: `FoodOrder`가 공통 데이터(`foodName`, `orderId`)와 공통 메서드(`pack()`, `deliver()`)를 제공

### 📌 다형성(Polymorphism)
- **정의**: 같은 인터페이스로 여러 객체의 실제 구현을 다르게 처리하는 것
- **종류**:
  - **컴파일 타임 다형성** (Compile-time): 메서드 오버로딩
  - **런타임 다형성** (Runtime): 메서드 오버라이딩 ← *이 예제가 해당*
- **이 예제에서**: `FoodOrder` 타입으로 `PizzaOrder`, `ChickenOrder`, `SushiOrder`를 모두 처리

### 📌 추상 클래스(Abstract Class) vs 인터페이스(Interface)

| 구분 | 추상 클래스 | 인터페이스 |
|------|-----------|---------|
| 상태(필드) | 가능 | 불가능 (Java 8 이상 제외) |
| 접근제어자 | 다양함 | public만 가능 |
| 상속 | 단일 상속만 | 다중 구현 가능 |
| 사용 시기 | IS-A 관계 | CAN-DO 관계 |

**이 예제**: IS-A 관계("피자는 음식 주문이다") → 추상 클래스 사용 ✓

### 📌 Template Method Pattern
```java
// 공통 프로세스의 틀을 제공하고, 가변 부분만 서브클래스에서 구현
public final void processOrder() {  // final: 오버라이드 금지
    prepare();    // 가변 부분
    pack();       // 고정 부분
    deliver();    // 고정 부분
}
```

## 실무 포인트

### ✅ 기존 코드와의 차이

**개선 전 (강한 결합도, 낮은 응집도)**
```java
public class OrderService {
    public void processPizzaOrder(String orderId) {
        // 피자 준비
        // 박스 담기
        // 배달
    }
    
    public void processChickenOrder(String orderId) {
        // 치킨 준비
        // 박스 담기
        // 배달
    }
    
    public void processSushiOrder(String orderId) {
        // 초밥 준비
        // 박스 담기
        // 배달
    }
    // → 새 음식 추가할 때마다 메서드 추가 필요 (Open/Closed Principle 위반)
}
```

**개선 후 (느슨한 결합도, 높은 응집도)**
```java
public class OrderService {
    public void processOrder(FoodOrder order) {
        order.processOrder();
    }
    // → 새 음식은 FoodOrder 상속만으로 자동 처리 (Open/Closed Principle 준수)
}
```

### 🔄 새로운 음식 추가 시나리오

**요구사항**: "버거" 음식 추가

```java
// 단 3줄! 기존 코드 수정 없음
class BurgerOrder extends FoodOrder {
    public BurgerOrder(String orderId) {
        this.foodName = "버거";
        this.orderId = orderId;
    }
    
    @Override
    void prepare() {
        System.out.println("버거를 그릴에 구웁니다");
    }
}

// 사용
FoodOrder burgerOrder = new BurgerOrder("ORD004");
processor.executeOrder(burgerOrder);  // 기존 코드 변경 없음!
```

### 🎯 SOLID 원칙 준수

| 원칙 | 적용 |
|-----|-----|
| **S**ingle Responsibility | 각 클래스는 하나의 음식 종류만 담당 |
| **O**pen/Closed | 새 음식 추가(확장)는 쉽고, 기존 코드 수정(변경)은 없음 |
| **L**iskov Substitution | 모든 `FoodOrder` 자식은 부모처럼 동작 |
| **I**nterface Segregation | 필요한 메서드만 구현 |
| **D**ependency
